Counts & reconciliation

ODS recon table rows against the counts the extract wrote to . Declared to Strata is the figure from MayoClinic_filecounts_MMddyyyy.txt — the same file Strata receives. The extract computes it with ReadLine(), so it counts physical lines, which only equals the record count while no field holds an embedded line break. Table rows are metadata counts by default (instant); exact counts scan the tables.

Two separate questions. Did every row reach the file? — answered by the record count. Is the file well formed? — answered by lines matching records. A row stays amber while its records are split across lines even though the counts reconcile, because the file is still wrong for anything that reads it one line at a time.
Note that without Count records in files the comparison is line-based, and a line-based Match is not proof: missing records and split records can cancel out. Press the button to settle it.

Updates and inserts over time

The reason the whole history is kept rather than just today. A total on its own says very little; the same total arriving as nearly all inserts, when yesterday it was mostly updates, says the dataset was re-keyed or rebuilt. Newest day on the right.

AdHoc lists

The AdhocHARList - *.csv files in that the next extract re-pulls for data correction. Near the end of each run, step 14 replaces the HB and PB Encounter lists with the missing parents it found. Extra entries — from Finance, say — are appended here between runs, and the next day's extract picks up everything. Changes are refused while the extract is running: anything written then is either read too late or replaced by step 14.
